# Production Sheet Export Implementation Plan

<!-- cspell:words xcodebuildmcp -->

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate an offline A4 production-sheet PDF from one saved `ProductionRun` snapshot and expose responsive preview, share, and print actions.

**Architecture:** A pure Dart export core maps the stored snapshot into an immutable document model and renders that model with `package:pdf`.
A Flutter presentation feature loads the bundled font, holds generated bytes, previews them, and delegates share and print to one replaceable `printing` adapter.
The existing result screen passes its saved snapshot directly into this feature.

**Tech Stack:** Dart 3.12, Flutter 3.44 or later, Material 3, `flutter_bloc`, `pdf` 3.13.0, `printing` 5.15.0, Flutter localization, Flutter unit and widget tests.

**Spec:** `docs/specs/2026-09-11-production-sheet-export.md`

## Global Constraints

- Export only a `ProductionRun` whose result screen has reached `ProductionResultStatus.saved`.
- Use the passed snapshot only.
- Do not read persistence or the current recipe and ingredient libraries.
- Do not recalculate, round, convert, add, divide, or distribute production quantities.
- Use A4 portrait pages and a minimum body font size of `9` PDF points.
- Use batch-oriented organization by default.
- Keep each repeated sub-recipe occurrence as a separate depth-first section.
- Keep a block together when it fits on a fresh page.
- Split an oversized section only between rows and repeat its headers.
- Reuse one successful `Uint8List` for preview, share, and print.
- Bundle the pinned Noto Sans KR font and OFL license.
- Make no network request during export.
- Preserve the existing Flutter Swift Package Manager integration.
- Do not add `share_plus`, a file cache, a temporary-file manager, an isolate abstraction, history UI, backup, restore, migration, or stored-run editing.
- Maintain `100` percent line coverage for reached Dart files.
- Resolve packages before formatting because this repository's formatter configuration comes from a resolved package.
- Run at most one simulator, emulator, Gradle, or Xcode job at a time.
- Do not send a shared file or submit a print job during runtime verification.
